# E11.2 canonical JSON, HTML and SARIF

`codestrata.reporting.canonical_views` projects one canonical envelope to three outputs.

JSON, HTML and SARIF copy hotspot order, ranking values, ownership ratios, co-change support and union, change-summary counts, coverage, freshness and comparison deltas from the supplied records. The HTML page does not sort hotspots, divide support by union, subtract before/after values, or choose outcome movement.

A first run (`has_baseline` false) prints `no baseline`, `delta unavailable` and `outcome movement unavailable`. Incompatible or insufficient movement stays labeled that way. `UNKNOWN` and `NOT_APPLICABLE` use those words. They are not a healthy badge. SARIF puts non-finding metrics in run properties. An UNKNOWN finding is `kind: review`, never a clean pass. Fingerprint `codestrata/v1` is the SHA-256 of finding id, rule id, subject id and occurrence key.

The page is a single HTML file. Styles are inline. Source paths and messages are escaped. No script or CDN URL is required.
