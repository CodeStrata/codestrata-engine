# R2-P04 — Baseline Engineering Health HTML + Architecture Map

## Goal
Deliver the R2 baseline `assessment.html` aligned with `reference/baseline-report.html` while using production Engine objects and renderer conventions.

## Required hierarchy
1. attention-first leadership summary
2. four Engineering Health outcomes
3. Architecture Map
4. Engineering Hotspots M22
5. ownership concentration M25
6. temporal co-change M26
7. Priority Actions
8. Coverage & Trust
9. supporting evidence / technical appendix

## Architecture Map
Source only from the existing canonical graph/AnalysisResult graph.
- canonical nodes only;
- canonical edges only;
- component/module grouping only when canonical membership exists;
- drill-down to canonical file/node/findings/evidence;
- visual layout positions are renderer-only;
- may overlay existing finding/hotspot/ownership context;
- may not invent edges, boundaries, centrality, risk, health or impact;
- graph unavailable state must be explicit;
- large-graph visual limits must be disclosed and must not silently change canonical downloadable data.

## Baseline semantics
No trend, movement or before/after section beyond an explicit “no baseline/comparison supplied” state where useful.

## Offline
No CDN/server dependency. Preserve escaping and local links.

## Validation
Generate reports from real fixtures, not hand-authored envelopes only. Check canonical parity, evidence links, UNKNOWN states and visual review.

After completion STOP. R2-G1 must pass before P05.
