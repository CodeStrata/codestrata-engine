# R2-P06 — Leakage-Safe Five-Snapshot Orchestrator and `trend` CLI

## Goal
Add the fixed-five committed-state trend journey without creating a second analyzer pipeline.

## CLI
Add:

`codestrata trend --repo <path>`

R2 does not add configurable commit count.

## Required orchestration
1. freeze one evaluation profile: Engine/analyzer/rules/config/feed/evaluation time;
2. obtain five requested slots from P05;
3. run the existing assessment pipeline for each available immutable tree;
4. bind each assessment source_revision to its SHA;
5. run Git history for S_i with explicit `head=S_i` (or equivalent reachability bound);
6. record per-slot source/config/feed/engine/result digests;
7. preserve failed/missing slots as UNKNOWN/unavailable;
8. leave worktree/index untouched;
9. if worktree is dirty, explicitly state trend uses committed HEAD and excludes uncommitted changes.

## Critical future-history rule
Do not call an unscoped `observe_repository()` / current-HEAD Git log for historical slots. S1 may not observe any file, commit, churn, co-change, ownership, graph edge or finding introduced after S1.

## Tests
Use adversarial five-commit repo. Add later-only hotspot/co-change/ownership/graph/finding and assert they do not appear in earlier snapshots.

## Prohibited
No database, no incremental-selective substitute, no LLM requirement.

Return evidence and stop.
