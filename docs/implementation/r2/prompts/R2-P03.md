# R2-P03 — Four-Outcome Engineering Health Projection Model

## Goal
Create/adapt the primary report view model so Engine and future Platform share the same repository Engineering Health taxonomy.

## Required outcomes
Exactly:
1. Architecture
2. Security
3. Quality
4. Maintainability & Technical Debt

## Required work
- project existing Architecture and Security evidence;
- create a first-class Quality report projection from existing Quality/testing evidence without a new analyzer family;
- group/relabel Technical Debt under Maintainability & Technical Debt;
- map testing-specific drivers under Quality;
- demote Inventory, Dependencies and Git to supporting context;
- demote Cloud Readiness, AI Readiness and legacy Modernization from peer headline outcomes;
- preserve canonical finding/evidence IDs;
- keep existing recommendation-backed Priority Actions;
- reconcile presentation coverage with canonical capability coverage so the UI cannot say Complete/Succeeded when required evidence/rules are unavailable.

## Presentation rules
Display labels may map canonical truth to Needs attention / No material issues observed / Insufficient evidence / Not applicable, but do not add canonical enums.

## Prohibited
No health score. No ranking/delta/lifecycle/movement math in report code.

## Tests
Extend assessment-head organization/parity tests. Assert exactly four headline outcomes and Quality present. Assert legacy heads not headline peers.

Return evidence and stop.
