Isolation points those tests at `tmp_path / "knowledge"`. Production lock timeout is unchanged (would need a separate knowledge-session story).

## PR text for `release/engine-next`

Title: `E04.3: Seal the effective digest and prove execution parity`

Body:

Seal canonical Effective RuleSet bytes from E04.1 composition and E04.2 overlays, binding resolver/DSL/capability versions, defaults, scoped settings and opaque attribution. Local unsigned parameters hash separately from the signed base. Package expiry cannot exceed included exception validity; wall-clock time is execution context and is recorded on admission, not in the digest. Changing parent order or effective settings changes the digest; changing a rendered message does not change the finding fingerprint. Preview cannot silently become production. A neutral local entrypoint executes compliant, violating and UNKNOWN fixtures plus snapshot previews through the production compiler and operators, returning typed diagnostics and expected/actual coverage bound to candidate/selector/effective-setting/input/Engine/DSL digests. Stale preview evidence, parameter changes, selector rebinding, scope violations and attempted production promotion fail. Ships `python -m codestrata.application.rules.effective --bundled` for the prebuilt Community catalog only; approval remains Platform-owned.
