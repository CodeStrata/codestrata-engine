## Known limitations and defects

- The legacy SQLite adapter remains available lazily for explicit compatibility
  tests and a future E02.3 maintainer export path. Production factory composition
  and fresh factory imports do not load `sqlite3`.
- Retention intentionally removes only incomplete owned `tmp/` and `staging/`
  content. It does not prune completed evidence automatically.
- File-store query limits are local MVP bounds (500 manifest/index records,
  16 MiB JSON, 1 MiB JSONL record); exceeding a bound is an explicit error.
- Windows/Python 3.14.7 differs from the configured Python 3.12 target; POSIX
  symlink and execute-bit cases remain skipped for the recorded host reasons.
- Defects opened against E02.2 acceptance: none.

## PR text for `release/engine-next`

Title: `E02.2: Replace production SQLite composition with bounded file artifacts`

Body:

Replace the production knowledge-store factory with a database-free
`FileKnowledgeStore`. Persist versioned repository, snapshot, run, and artifact
JSON manifests plus rebuildable bounded JSONL indexes and content-addressed
SHA-256 blobs. Completed runs appear only after verified artifacts are atomically
finalized. Add streaming reads, local health, safe retention, path and size
bounds, corruption detection, and interruption/collision/concurrent-reader/
disk-full coverage. A fresh installed wheel works with `sqlite3.connect`
blocked; existing SQLite files, supplied baselines, source, and unrelated files
remain untouched. Legacy SQLite exports stay lazy for E02.3 compatibility work.
