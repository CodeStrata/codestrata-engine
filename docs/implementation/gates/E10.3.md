## Known limitations

- Controlled rerun isolation relies on explicit rerun references identifying changed and held constant dimensions. In the absence of controlled paired reruns, multi-dimensional changes are strictly reported as `mixed` or `undetermined`.
- Feed-driven vulnerability updates are distinguished from source code modifications; however, rules without feed versioning or advisory metadata rely on top-level scan feed digests for automatic cause separation.
- Comparison across all five families operates purely on Engine models and scan results with no database or external platform service dependencies.

## PR text for `release/engine-next`

**Title:** `E10.3: Separate source, feed and configuration causes`

```text
Implement M31 cause attribution enhancements, separating source, feed, configuration,
coverage, and engine causes across scan comparisons, findings lifecycle, and outcome movement.

Key capabilities:
- Same-code feed changes labeled feed-driven (attribution='feed_only', label='feed-driven', is_feed_driven=True)
- Feed-driven CVE changes protected from being called customer code deterioration (customer_code_deterioration=False)
- Controlled rerun isolation: when source and feed both change, paired reruns isolate causes without guessing dominant cause
- Default non-guessing policy: multi-dimensional input differences without reruns report 'mixed' or 'undetermined'
- Five-family comparison: compares Inventory, Architecture, Security, Quality, and Git families without Platform imports, DB, or hidden baseline selection
- Preserved explicit qualifying changes and denominators across all comparisons
- Added ControlledRerunReference schema and extended CauseAttribution model
- Delivered 7 controlled comparison fixtures in tests/application/incremental/fixtures/e10.3/
- Fully integrated with ScanComparisonService.compare_results, compare_with_lifecycle, compare_m31, and isolate_controlled_reruns
```
