## Requirement mapping

| Requirement | Implementation |
|---|---|
| `codestrata trend --repo <path>` | `register_trend_command()` in `cli/trend.py`; registered after compare |
| Fixed five; no configurable count | P05 `SERIES_SLOT_COUNT = 5`; CLI has no `--max-count` |
| Freeze Engine/rules/config/feed/time | `freeze_evaluation_profile()`; one clock passed to every `run_assessment` |
| Reuse P05 selection/materialization | `select_first_parent_series` + `SnapshotWorkspace` |
| Assess each available immutable tree | `_assess_slot` calls existing `run_assessment` on extracted `S_i` |
| Bind `source_revision` / `git_head` to `S_i` | `seal_assess_canonical_records(..., head=S_i)` and `history_head` on `run` |
| History ends at `S_i` | `observe_repository(..., head=S_i)` → `git log S_i`; live HEAD not used |
| Preserve missing/failed slots | Always five records; `unavailable` / `failed` stay visible |
| Worktree untouched | Fingerprint HEAD/index/dirty before/after; extract + gitdir only in temp |
| Dirty worktree excluded | Committed trees only; `DIRTY_WORKTREE_NOTICE` when dirty |
| P05 limitations surfaced | Slot `limitations` include `skipped_submodule:` / `unsupported_non_utf8_path` |
| Non-UTF-8 paths | Binary `ls-tree`; `unsupported_non_utf8_path` when decode fails |
| Pin knowledge writes off user tree | Knowledge directory redirected under the trend output root |
| No trend HTML / P07 bundle | Writes run-local `trend-series.json` + per-slot assess outputs only |

User checkout is never `git checkout`'d. Historical `S_i` is a temp tree plus a
`gitdir` file pointing at the real object store. Git history is bounded by
`head=S_i`. Scanner/graph/findings read the materialized `S_i` files.

## Limitations

- Independent reviewer not recorded.
- Full Engine suite not re-run.
- Durable trend retention, adjacent/span comparisons, and trend HTML remain P07–P09.
- Per-slot assess still writes existing baseline HTML/JSON under the run-local
  output root; that is not the P09 trend report.
- Feed pin overlays the current evaluation feed into snapshots that lacked it
  and records `pinned_feed_overlay`.
- Knowledge persistence is redirected under the trend output directory so the
  user worktree is not used as a store.
