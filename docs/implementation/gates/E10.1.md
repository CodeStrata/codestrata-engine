## Known limitations

- Finding identity matching requires subject and occurrence alignment when `identity_key` is not explicitly supplied; unstructured changes across both subject and occurrence simultaneously will treat candidate occurrences as new.
- Binary violations remain `unchanged` until fully eliminated under complete coverage; intermediate severity modifications to binary violations are recorded as configuration policy overrides, not source code fixes.
- Metric deltas require exact unit and scope parity; differing units or scopes evaluate to incompatible deltas without synthetic conversion.

**Title:** `E10.1: Match finding lifecycle and compatible metric deltas`

```text
Implement M28 versioned finding matching and compatible metric deltas across
two explicit canonical states.

Key capabilities:
- Enforce 6-state finding lifecycle: new, resolved, improved, worsened,
  unchanged, unknown.
- Preserve finding identity across title/description changes and path renames.
- Enforce M28 invariants: coverage loss never resolves findings (evaluates to
  unknown); severity overrides are configuration adjustments, not code fixes;
  binary violations remain unchanged; persistent non-binary findings
  improve/worsen only against declared compatible magnitude comparators.
- Calculate metric deltas as candidate - base with unit, scope, and formula
  compatibility pinning.
- Cover all 11 required fixtures with 38 passing unit and integration tests.
```
